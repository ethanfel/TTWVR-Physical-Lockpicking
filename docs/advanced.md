# Building from source

Players can install the [ready-to-play ZIP](../README.md#install). The commands below are for people building the addon.

## Build the DLL

From the **repository root** on Linux, install CMake 3.24+, the i686 MinGW-w64 C++ toolchain and Khronos OpenXR headers. Set `OPENXR_INCLUDE_DIR` if `openxr.h` is outside `/usr/include/openxr`.

~~~sh
cmake -S . -B build32 -DCMAKE_TOOLCHAIN_FILE=cmake/mingw32.cmake -DCMAKE_BUILD_TYPE=Release -DLOCKPICK_TEST_INPUT=OFF
cmake --build build32 --target lockpick
cmake -S . -B build-tests -DCMAKE_BUILD_TYPE=Debug
cmake --build build-tests
ctest --test-dir build-tests --output-on-failure
~~~

To test OpenVR without starting Fallout, build the optional MinGW target `lock_host_openvr_test` and run its EXE under Wine or Windows with arguments `118 "path/to/TTWVR.dll"` (use `117` or `116` for an older host). It drives the original backend with simulated controller and compositor responses. Add a third argument to exercise other controller setups. Use `direct` for resolved methods, `wrapped` when both backends already have a controller handler, or `mixed` when only OpenXR has one.

## Build the player archive

Compile `tools/export_hardware.cpp` for the build machine. The asset preparation tools use Python 3.11 or 3.12 and the packages listed in `release/requirements.txt`. To stage those tools, use `release/package.py` with the DLL and both exporters, and extract its output to a working directory. Run `prepare.py` there with a stock TTW profile.

~~~sh
python prepare.py --data "GAME/Data" --ttwvr "MODS/Tale of Two Realities 1.1.8" --mods "MODS" --modlist "VR_PROFILE/modlist.txt" --output "prepared"
~~~

From the source checkout, build the installable ZIP. This step binds meshes to the game's virtual texture paths and stores the shader changes as small deltas. At startup the addon applies matching deltas to the installed shader packages and caches the results under `Data/LPVR`.

~~~sh
python release/package_mod.py --prepared "prepared" --data "GAME/Data" --dll "build32/TTWVRPhysicalLockpicking.dll" --output "TTWVR-Physical-Lockpicking-1.1.8-r5-Ready-to-Play.zip"
~~~

Developers using the separate OpenXR capture path need the full locally prepared assets, the addon’s manifest registered with the registry file generated by `openxr.py` in the game's prefix, and `TTWVR_LOCKPICK_CAPTURE_LAYER=1`. Ordinary play uses TTWVR's own input backend.
